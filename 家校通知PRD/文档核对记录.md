#### 一、核对范围

本次核对六份 PRD 与 V25 的通知来源、通知类型、跨端编辑、学校可见范围、代发身份限制、草稿范围，以及三个 Web 菜单到通知主页面的跳转关系。小程序页面和模板按照用户要求只保留资料，本轮不修改、不发布。

#### 二、已确认口径对齐

| 项目 | 需求口径 | 对齐记录 |
|---|---|---|
| 通知类型 | 仅普通通知、美文通知；链接是正文形式 | 共通规则、三份 Web PRD 和教师/家长 PRD 已统一 |
| 通知来源 | 教师端、学校端、平台（代理商名称）、平台端；没有家长来源 | 三个 Web 筛选与列表显示使用统一来源；家长端只接收 |
| Web 新发布 | 固定为美文通知 | 三份 Web 新增页面统一按美文通知编辑 |
| 跨端编辑 | 在原有账号权限范围内，可编辑各端发布的通知；未有任何阅读/确认/签字且未到截止时间 | Web 编辑入口和保存校验均按条件限制；编辑通知保留原来源和类型 |
| 普通通知编辑 | 普通通知正文按一个文本内容块显示和编辑 | 可编辑的普通通知进入 Web 时合并为一个文本块，保存后仍是普通通知 |
| 学校可见范围 | 学校可见本校教师、学校、代理商及平台端通知，不区分个人名义或学校名义 | 学校端按同校通知显示；新增可见范围不扩张原有编辑权限 |
| 代发身份 | 代理商和运营后台代发必须以学校名义，开关不可关闭 | 发布设置中开关固定开启；提交时仍保留该限制 |
| 草稿 | 代理商 Web、运营后台无草稿；教师草稿仅保存通知内容 | Web 发布页不展示草稿按钮；小程序原型未改动 |
| Web 菜单关联 | 主菜单、页面框架由对应基线项目管理 | 三个 Web 菜单将家校通知指向 GitHub V25 页面，子页面由通知页面路由承接 |
