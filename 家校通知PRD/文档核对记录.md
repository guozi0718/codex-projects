# 家校通知 PRD 文档与原型核对记录

任务：T-20261118-03｜各端 PRD 与原型对齐  
核对日期：2026-11-18  
文档批次：V0.4（修改中、待评审、未定版）  
本轮原型：家校通知 V22；学校 Web v0.57、代理商 Web v0.61、运营后台 v0.66。

#### 一、核对范围

核对六份 PRD 的章节结构、产品表达、字段/流程/异常说明、与三个 Web 端固定评审原型的对应关系，并按用户刚提供的四项批注修订相应原型规则和文档。客服管理项目只读作为 PRD 框架和详细程度的参照，不修改参考文档，也不搬用客服管理业务规则。

#### 二、文档结构与表达

1. 全端共通规则和五份分端 PRD 沿用用户指定的客服管理 PRD 十章框架。
2. 页面说明按入口、字段、控件、必填和默认值、操作顺序、校验、异常表现、操作后结果及验收场景展开。
3. 采用用户能直接理解的产品语言，描述页面行为和业务结果；不把技术方案、开发框架、代码要求写入需求正文。
4. 已确认规则与待确认问题分开记录；用户尚未确认的边界不写成确定方案。

#### 三、四项批注核对

| 序号 | 批注 | 原型与 PRD 状态 |
|---|---|---|
| 1 | 删除后不在前端留“已删除”状态，后台保留删除快照、操作人和时间；按 Q21/Q30 选择的 A 口径保留完整范围 | V22 从普通记录集合移除已删除通知，隐藏留存记录包含通知内容、发布设置、对象范围、个人阅读/确认/签字记录、操作人和删除时间；三个 Web PRD 已写明无删除列表和恢复入口。该数据留存目前由原型模拟，不代表已接入真实后台。 |
| 2 | 截止时间默认空 | V22 新建通知保持空值；用户未选时间时不填入日期；30 个自然日有效期规则仍按既有口径执行。三份 Web PRD 的字段、异常和验收场景均同步。 |
| 3 | 一键提醒仅针对未读对象 | 三个 Web 端按学生汇总阅读状态和教师个人阅读状态分别提供提醒；学生未读时提醒该学生所有关联家长；已读未确认/未签字不提醒；没有未读对象时不显示提醒按钮；不展示发送任务状态，失败不自动重试。三份 Web PRD 已同步。 |
| 4 | 发布状态筛选顺序 | V21 原型已有“全部、待发送、已发送、已截止”的顺序；V22 保留该顺序，不增加草稿、已删除或已撤回选项。共通规则和三份 Web PRD 保持一致。 |

小程序页面和模板资料按用户此前要求保留，本轮不修改小程序界面。V22 共用文件仅在老师小程序的提醒处理上保留 V21 交互；三项 Web 行为调整限定在三个 Web 端。

#### 四、其他已确认内容

1. 学校 Web 两步发布；代理商 Web 和运营后台三步发布。
2. 三个 Web 端使用各自基线项目菜单与框架，“校务管理→家校通知”是功能入口。
3. 学生统计按通知选择的对象范围显示年级、班级和学生；筛选后的统计数随列表筛选结果联动；无结果时数值为 0 并显示空状态。
4. 只读、需确认、需签字三种查收方式分别显示适用指标，不展示完成率。
5. 正常列表发布状态不包含草稿或已删除；删除不通知接收人。
6. 正文全文背景、附件格式与数量限制、统计列表字段、默认筛选、日期格式等已确认规则继续按共通规则和分端 PRD 执行。

#### 五、待确认边界

#### 七、核对边界

本文记录本地文件静态核对结果，不运行自动化测试。真实消息投递、真实后台快照留存、真实账号权限、真实校区名单和 PDF 文件下载不由静态原型提供；不将原型模拟描述为生产系统行为。
