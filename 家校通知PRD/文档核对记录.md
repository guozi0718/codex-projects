#### 已完成核对

1. 六份 PRD 均采用相同的十章骨架：需求背景与目标、一期范围、业务名词/数据/规则、原型与来源、页面清单、功能详细说明、数据权限与跨端一致性、验收标准、端特有规则、文档边界与交付说明。
2. 页面细节按用户指定模板展开，包含字段、控件、默认值、操作顺序、校验、空态/失败态、用户后续操作和验收场景。
3. 逐条检查用语是否属于产品需求；规则改写为用户可见行为、业务结果和异常处理，同时保留已确认的业务留存要求。
4. 跨端统计规则已统一：只读/确认/签字的指标分别显示；统计不含完成率；学生表格显示年级、班级、姓名、阅读情况、查收结果和明细；筛选后概览数值随筛选更新；无匹配时统计为0并显示空状态。
5. 发布状态筛选顺序写为全部、待发送、已发送、已截止；Web无草稿或已删除状态。
6. 学校 Web 两步发布；代理商与运营后台三步发布；三个小程序页面材料保留，本轮不修改原型。
7. 提醒对象口径已根据用户明确要求写为已确认；每个已选整班后续新增学生按整班规则纳入。编辑后有效期的起算点及显式截止时间与重新计算的关系为Q66–Q68待确认；全年级之后新建班级是否纳入为Q70待确认；代发流程改选目标学校后的内容和名单处理为Q71待确认。
8. Q21/Q30 选择的删除留存口径已写入共通规则：保留删除时的通知内容、发布设置、对象范围、个人阅读/确认/签字状态、操作人和时间；普通页面不展示。
9. PRD 与 V21 当前固定原型版本映射见本目录索引和登记文件；运营后台链接使用 v0.63-b60e784e6a 目录。

#### 已发现的原型差异

本次 PRD 按用户最新明确要求记录业务规则。对照本地 V21 原型后，发现两处页面行为还未与需求一致：截止时间默认应为空，但 V21 当前预置了当前时间加30天；一键提醒应只针对学生汇总未读对象，但 V21 当前还提供“未完成”筛选入口。当前 PRD 按已确认的用户口径编写；这两处原型差异在原型同步前不视为已实现。
