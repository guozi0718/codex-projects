#### 2. 对应原则

1. Web端主菜单、页签和页面框架由对应基线项目管理；家校通知内容从该端的“校务管理→家校通知”菜单打开。
2. PRD 固定链接指向对应评审版本；如果原型与用户已确认业务要求有差异，应记录为原型待改项，不能将页面现状写成已经确认的产品规则，也不能称为两者已完全一致。
3. 学校 Web 是两步发布；代理商 Web 和运营后台先选学校，再填写内容、准备发布，共三步。
4. 教师、家长小程序页面和模板资料本轮保持本地留存；不能用 Web 发布包替代小程序原型。
5. 用户明确确认的规则与原型页面一致；未确认项单独标注，不能用页面演示数据替代业务确认。
6. 参考项目的客服管理文档只用于本 PRD 的写作结构，不把客服业务对象或规则移入家校通知。

#### 3. 原型变更后的文档同步步骤

1. 先说明原型变化影响哪些端、哪些页面和哪些业务规则。
2. 发布受影响端的固定版本，并记录可复核的版本链接和提交号。
3. 同步更新该端 PRD；跨端规则变化时同时更新全端共通规则。
4. 更新与新版本匹配的页面截图；历史截图标明历史版本，不当作当前截图。
5. 更新索引、发布登记和核对记录中的版本、链接、提交和本地源。
6. 核对每个原型页面是否有对应 PRD 描述，每条已确认的PRD行为在原型中是否有对应页面/交互。
7. 若问题仍未确认，继续标注待确认；确认后再将规则移入已确认正文并更新受影响原型和文档。
