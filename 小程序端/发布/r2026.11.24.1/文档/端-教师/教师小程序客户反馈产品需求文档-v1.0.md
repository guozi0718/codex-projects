本文只说明教师小程序客户反馈相关页面、页面状态和异常处理。教师与家长端分开编写。当前候选继承完整小程序项目的反馈页面，不改变活动原型基线。

#### 1. 需求背景与目标

学校 Web 客户反馈规则已收敛为一问一答：一条记录由提问方提交一次，受理方答复一次；答复后记录结束。教师小程序此前候选仍保留追问、撤回及“已撤回”样例，需要与学校 Web 的这项调整保持一致。

本次还在教师提交表单的“反馈类型”字段前增加只读基本信息卡，便于教师提交前确认当前角色对应的学校与教师姓名。最新候选同时将卡片两行分隔线延伸至卡片内容区边缘，并统一学校、老师字段的字号与常规字重。

目标：

1. 教师可以在本人反馈列表查看、筛选并打开自己提交的记录。
2. 每条记录只显示一次提交及受理方至多一次回复；收到回复后本条结束，后续问题通过新增一条反馈处理。
3. 教师提交页在“反馈类型”之前显示学校名称、老师名称；两项从当前登录教师角色资料回写，不能手动编辑。
4. 提交资格按当前教师身份、有效学校任职关系及现行反馈提交权限核对；原型示例不声称已连通真实权限服务。
5. 保留正文500字、图片最多9张且每张不超过10MB等已确认规则。

|功能|本次范围|本次不改|
|---|---|---|

#### 3. 业务名词、数据来源与基础规则

##### 3.1 本端规则

|业务项|教师端规则|
|---|---|
|反馈编号|一条反馈唯一编号，同时作为记录ID；不另设第二个记录ID。提交后不变|
|反馈类型|问题反馈、功能建议；创建后只读|
|正文|必填，去除首尾空白后不得为空，最多500字|
|附件图片|JPG/JPEG/PNG；提交时最多9张，每张不超过10MB；附件归属本次提交|
|状态|仅待回复、已回复。新记录为待回复；受理方答复一次后为已回复|
|消息轮次|最多一条教师首条反馈和一条受理方公开回复；不在原记录继续追问|
|记录结束|已回复后本条只读并结束；后续不同问题从列表新建独立反馈，产生新编号|
|排序|列表按记录最近更新时间从新到旧；详情沟通记录按消息时间从新到旧，较新的消息在上|
|附件查看|本人可在记录详情查看首条反馈及公开回复的图片；打开图片不改变状态|

##### 3.2 身份、权限与数据范围

1. **当前教师角色**：双身份账号切换到教师角色时，只展示教师角色提交的本人反馈；家长角色记录不并入教师列表。
2. **本人记录隔离**：列表按当前教师角色和当前提交账号查询，不按当前学校筛掉本人历史记录。同校其他教师账号不能查看该教师记录。
3. **学校 Web 隔离**：教师小程序来源记录不回显到学校 Web；学校账号只查看其授权范围内学校自己提交的反馈。
4. **受理方范围**：提交时按该校当前负责人配置交给代理商或运营平台。受理组织内有权限的账号可查看和答复；非指定受理方不可查看正文、图片或历史消息。
5. **任职及操作权限**：提交时重新核对当前账号处于教师角色、存在有效学校任职关系，并具有当前学校配置的反馈提交权限。页面可以打开不代表可以提交。
6. **权限变化**：任职关系或提交权限在填写期间失效时，最终提交被拒绝，不创建反馈记录，提示当前资格不满足；已输入内容和已选择图片保留，供教师退出或处理后重新提交。
7. **负责人变更**：记录仍为待回复时，按学校最新负责人配置转给新受理组织。转派后原受理组织立即失去正文和附件访问权；新受理组织可继续查看完整历史。教师本人查看权不变。
8. **学校与学生信息**：教师反馈保存提交时学校及提交人信息；教师反馈不关联学生。详情按已确认规则不展示学校快照或学生快照。

##### 3.3 受理方一问一答

1. 教师提交成功后，记录为待回复，时间线出现教师“提交”消息。
2. 受理方只可对该记录作一次公开回复。回复成功后状态更新为已回复，沟通记录展示回复及时间，当前记录结束。
3. 同一记录不能由教师再次发送问题，也不能由受理方再追加第二条回复。
4. 教师后续发现新问题时必须另建反馈。新反馈有独立编号、提交时间、状态和记录排序。
5. 通知是否送达与反馈状态是两件事；通知失败不能把待回复变成已回复，也不能让用户误认为记录已得到答复。

本期反馈页面字号参照家长端“我的—添加孩子”页面：页面标题16.5px、字段标签12px、正文和选项13px，辅助提示约11.5px。教师基本信息卡的字段名和值保持常规字重。字号样式仅作用于反馈列表、反馈详情和反馈表单弹窗，不改变帮助、客服或其他小程序页面。

###### 6.1.2 页面进入、筛选与记录卡片

1. **入口**：教师从“我的”→帮助与反馈→反馈建议进入本人反馈列表。教师原帮助内容之外的页面不随本次修改。
2. **状态筛选**：只显示“全部”“待回复”“已回复”。切换筛选只改变当前列表，不改变记录状态。
3. **权限范围**：仅展示当前教师角色、当前账号提交的记录。不因当前登录教师调整任职学校而隐藏本人历史记录；不展示同校其他教师或家长记录。
4. **记录卡片**：显示反馈类型、当前状态、正文摘要及最近更新时间。状态置于卡片右侧；日期时间靠右对齐。卡片整体可点入详情，不再出现“查看详情”文字。
5. **列表排序**：记录按最近更新时间倒序；受理方回复后更新时间变化，记录移至列表较前位置。
6. **新增入口**：点击“＋提交反馈”打开一张空白表单；不复用历史记录，不预填旧记录正文或附件。

###### 6.1.3 空态、读取异常与返回

|场景|页面表现|后续处理|
|---|---|---|
|当前没有本人记录|显示“暂无反馈记录”及现有空态文案；不显示其他账号的记录|可点“提交反馈”新建记录|
|当前筛选无记录|显示该状态下无记录的空态；保留筛选条件|切换其他状态或“全部”|
|列表读取失败|说明暂时无法读取并提供重新加载|不得用“暂无反馈记录”冒充读取成功的空列表|
|用户当前非教师身份或账号变化|按当前角色重新读取；无法确认身份时不展示受保护记录|重新登录或切回教师身份|
|点击一条本人记录|进入对应反馈详情|返回时保留列表原筛选及滚动位置|

###### 6.2.3 提交流程

1. 教师以当前教师角色打开表单。
2. 页面读取当前教师角色对应的学校名称和教师名称，并在反馈类型上方展示。
3. 教师选择问题反馈或功能建议，填写正文，可选添加图片。
4. 点击提交时再次核验账号、教师身份、当前有效学校任职关系及当前有效的反馈提交权限。
5. 全部校验通过后创建一个新反馈编号，保存首条“提交”消息，初始状态为待回复，进入本人反馈列表。
6. 提交失败时留在原表单；不得生成半条记录或丢弃正文、类型及已通过检查的图片。

###### 6.2.4 资格、内容与附件校验

|校验项|通过条件|不通过时的处理|
|---|---|---|
|教师身份|当前账号仍以教师身份提交|不创建反馈编号；说明当前身份不可用并保留表单|
|任职学校|提交时仍存在有效教师—学校任职关系|不创建记录；说明学校任职信息已变化，重新进入后读取最新资料|
|提交权限|当前教师在当前学校具有反馈提交资格|不创建记录；说明当前账号暂无提交资格。具体权限名称沿用学校现有权限，不另造权限码|
|学校/姓名显示|任一必需信息为空或无法读取|禁止提交并说明缺失项；不得把空值伪装为有效身份|
|反馈内容|去空格后至少有一个字符，长度不超过500字|空白或超限时提示对应原因；保留已输入内容|
|图片数量|最多9张|第10张不加入；先前已选且有效图片继续保留|
|图片格式|仅JPG/JPEG/PNG|拒绝该文件并提示支持的格式；不清除其他有效图片|
|单张图片大小|每张不超过10MB|拒绝超限图片，保留其他有效图片|
|图片读取中|所有待选图片读取完成|暂不允许重复提交；读取失败时说明原因，可重新选择|

教师提交权限是业务校验；原型中的示例教师具备提交资格仅用于页面预览，不代表系统已验证真实账号权限。学校真实名称与教师姓名从当前登录角色资料回写，不由教师在此页面填写。

###### 6.2.5 取消、重复点击与失败恢复

1. 未编辑表单时点击取消或顶部返回，直接关闭表单，不生成记录。
2. 已有未提交的类型、正文或图片时，点击顶部返回或底部取消，在手机原型框内打开底部“放弃编辑”确认层。标题为“放弃编辑”，正文为“确认放弃当前编辑内容吗？确认后将清空内容，不可恢复。”按钮为“取消”和“确认放弃”。点击“取消”只关闭确认层，原类型、文字和已选图片全部保留；点击“确认放弃”后清空本次未提交内容并退出表单。没有未提交内容时直接退出，不显示确认层。
3. 提交正在处理时再次点击，不应产生多条反馈；重复操作至多产生一条反馈编号。
4. 校验失败或提交失败时保留仍有效的类型、正文和图片；不得清空表单后要求教师重填。
5. 任职学校、权限或登录身份在填写期间变化，以提交时最新情况为准；如资格失效则按本节资格规则拒绝。

###### 6.3.2 反馈信息卡

1. 反馈编号显示在详情信息区前部；该编号也是记录ID。

3. 完整首条正文及首条图片在反馈信息区查看。
4. 不另列“提交时间”字段；首条提交时间显示在沟通记录中的“提交”消息右侧。
5. 详情不显示学校快照、学生信息、提交人联系电话、受理组织内部资料或内部处理消息。

###### 6.3.3 沟通记录与状态

1. 时间线按消息发生时间倒序排列，最新消息在上；时间靠消息行右侧对齐。
2. 所有记录均展示教师本人首条“提交”及其提交时间。
3. 待回复记录只展示“提交”，状态为待回复。
4. 已回复记录展示一条受理方“回复”及其回复时间，排在“提交”之前，状态为已回复。
5. 任何消息及附件提交后均只读；页面不显示追问、撤回、修改或删除按钮。
6. 受理方答复已经出现但详情状态仍为待回复时，重新读取最新记录；不得显示可继续发言的入口。

###### 6.3.4 无权、失效或读取异常

|场景|页面表现|处理|
|---|---|---|
|反馈编号缺失或格式无效|不展示反馈内容|返回本人列表并说明无法打开该记录|
|记录不属于当前教师账号或当前角色|不透露记录是否存在及其内容|拒绝展示并回本人列表|
|受理方已回复，页面仍持有旧状态|显示最新答复和已回复状态|隐藏所有后续操作入口|
|记录读取失败|说明暂时无法读取并提供重试|不将失败显示成无消息的空记录|
|图片打不开|保留消息正文和时间|单独提示图片暂不可查看，不改变反馈状态|
|用户身份切换|按新角色重新确认权限|家长记录不能因同一手机号或同一登录账号而混入教师列表|

#### 7. 业务信息与学校 Web 对齐

##### 7.1 一条反馈应关联的信息

|信息|教师端保存规则|页面是否展示|
|---|---|---|
|反馈编号/记录ID|同一编号，不创建第二个记录ID|列表和详情可见|
|来源角色、提交账号|取当前登录教师角色及稳定账号标识|用于本人隔离；详情不显示账号标识|
|提交人姓名、联系电话|提交时身份快照|正文区不显示联系电话|
|学校及所在地区|取提交时当前登录教师角色有效任职学校|提交表单仅展示学校名称；详情不展示学校快照|
|学生关联|教师反馈不关联学生|不展示|
|反馈类型、正文、标题|小程序采集类型与正文；本端没有标题输入|类型和正文展示；标题不要求用户填写|
|附件|关联同一反馈编号和对应消息|提交前可管理；提交后只读|
|提交/更新时间|首次提交和最近公开消息的发生时间|列表显示最近更新时间；详情时间线显示每条消息时间|
|状态|待回复、已回复|列表筛选、卡片及详情展示|
|受理组织|提交时由学校当前负责人配置确定；待回复时按最新配置转派|不向教师展示内部组织分配资料|
|公开消息|首条提交及受理方至多一次回复|详情按消息时间倒序展示|

##### 7.2 与学校 Web 的边界

1. 学校 Web v1.14的原规则是：“学校提交首条反馈后等待受理方回复；收到回复后，这条记录结束对外问答。”教师小程序按相同的一问一答业务边界执行，已提交内容和受理方回复均不可修改，也不提供追问、撤回或删除。
2. 教师小程序的页面和角色仍由本端定义；本次只沿用已核对的一问一答边界，教师记录不变为学校来源记录。
3. 学校账号不能因教师所属学校与学校Web相同而查看该教师记录；学校 Web 不回显教师小程序反馈。
4. 代理商或运营平台受理后，教师仅能查看公开处理答复；受理方内部资料和内部消息不在教师详情显示。

#### 8. 异常和恢复规则

|编号|场景|预期结果|
|---|---|---|
|T-ERR-01|登录账号不是教师角色|不开放受保护记录；切换到教师角色后重新读取|
|T-ERR-02|教师已离职或任职学校变化|新的提交按最新身份复核；不影响本人历史反馈查看权|
|T-ERR-03|教师没有当前学校反馈提交资格|拒绝创建；给出必要提示并保留表单|
|T-ERR-04|学校名称或教师名称缺失|卡片显示缺失状态且不可提交；不得以空值建立记录|
|T-ERR-05|正文为空、全空格或超过500字|指出内容原因；不创建记录，已填写内容保留|
|T-ERR-06|图片格式不支持、超过10MB或选满9张|仅拒绝不合格或超额图片；已选的有效图片保留|
|T-ERR-07|提交时连续点击|一个用户动作最多生成一个反馈编号|
|T-ERR-08|受理方已回复但列表尚未刷新|详情按最新记录状态展示已回复，时间线只显示一条受理回复|
|T-ERR-09|反馈详情无权或编号错误|不泄露正文、图片或编号归属；返回本人列表|
|T-ERR-10|刷新、关闭或退出未提交表单|按取消规则确认是否放弃；没有未提交内容时直接退出|
|T-ERR-11|记录、图片或消息读取失败|显示明确失败状态，提供重试；不伪装成空记录|
|T-ERR-12|历史数据含已撤回状态|不将其改写成待回复或已回复，不删除历史记录；旧数据展示方式需在数据迁移范围内单独确认|

#### 9. 需求验收标准

1. 教师列表只含当前教师角色和当前提交账号的反馈；同校其他教师记录不可见。
2. 列表仅有全部、待回复、已回复筛选；不显示已撤回筛选。
3. 提交表单在反馈类型之前显示基本信息卡；学校名称和老师名称为只读，并与当前登录教师角色匹配；两行分隔线铺满卡片内容区，字段名和值字号一致且不加粗。
4. 任职关系、账号角色或反馈提交资格无效时不能创建反馈；失败保留表单和有效图片。
5. 新记录只生成一个反馈编号，状态为待回复；编号同时作为记录ID。
6. 每条记录时间线仅有首条提交和受理方至多一次回复；消息按时间倒序显示，最新消息在上。
7. 回复后状态为已回复，不能编辑、删除、追问或撤回；发现其他问题只能新增独立记录。
8. 正文、图片张数/格式/单张大小均按本文件字段规则校验。
9. 详情不显示学校/学生快照，不单独显示提交时间字段；提交时间出现在“提交”时间线消息右侧。
10. 学校 Web 只显示学校来源反馈，不显示教师来源记录。
11. 未经用户确认不得将本候选标记定版或切换活动原型基线。

#### 10. 文档边界与待核实项

本文件是客户反馈优化第一期教师端候选需求，不是技术开发说明。教师当前账号姓名、任职学校、权限和受理方均应以实际登录与学校配置为准；文中样例名仅用于页面演示。

学校 Web PRD v1.14未列出教师小程序的具体权限编码、服务端字段名或通知文案。本端不新增虚构权限码，也不把原型演示数据表述为线上已生效。

若上线数据中存在旧版“已撤回”记录，需与负责数据迁移的一方确认其只读展示方式；不得将其状态直接改写为待回复或已回复。此候选原型不包含旧数据迁移页面。
