### 智小徽小程序客户反馈功能优化第一期产品需求文档｜家长端

产品版本：客户反馈功能优化第一期  
文档编号：PRD-FB-MINI-P-20261123  
文档版本：v0.8（修改中，待评审）  
文档状态：候选，未定版  
适用端：家长小程序

本文只说明家长小程序客户反馈相关页面、页面状态和异常处理。教师与家长端分别编写；本端保留家长已有的反馈页面，并按学校 Web 已核对的一问一答规则调整。

#### 1. 需求背景与目标

学校 Web 客户反馈规则 v1.14 将同一条记录收敛为首条反馈与受理方一次回复：学校提交首条反馈后等待受理方回复；收到回复后，这条记录结束对外问答。家长小程序也采用同一业务边界。家长已提交的记录不能追问、撤回、修改或删除；后续事项通过新增一条反馈提出。

本次还在家长提交页的反馈类型字段之前增加只读基本信息卡，显示当前所选孩子对应的学校名称和学生名称。新建反馈只允许所选孩子处于在读状态。

目标：

1. 家长可以在本人反馈列表查看自己提交的记录，且记录范围不因当前切换的孩子改变。
2. 一条记录只显示家长首次提交和受理方至多一次回复；收到回复后本条结束。
3. 新反馈提交表单固定关联打开表单时当前选中的孩子，并在反馈类型上方回写学校名称和学生名称。
4. 只有当前所选孩子提交时为在读，家长才可以创建新反馈；不符合条件时说明原因并保留未提交内容。
5. 保留正文最多500字、附件最多9张且每张不超过10MB等现有已确认限制。

#### 3. 业务名词、数据来源与基础规则

##### 3.1 家长端字段规则

|业务项|家长端规则|
|---|---|
|反馈编号|一条反馈的唯一编号，同时作为记录ID；不另设第二个记录ID，提交后不变|
|反馈类型|问题反馈、功能建议；创建后只读|
|反馈内容|必填；去除首尾空白后不得为空，最多500字|
|附件图片|选填，支持JPG/JPEG/PNG；每条首条反馈最多9张，每张不超过10MB；提交前可移除未提交图片|
|基本信息卡|显示学校名称、学生名称；由表单打开时当前选择的孩子及其学校关系回写，不可编辑|
|孩子状态|仅当前选择的孩子状态为在读时允许创建新记录；状态不明、关系失效、毕业或离校均不允许提交|
|状态|仅待回复、已回复；提交成功为待回复，受理方回复一次后为已回复|
|消息轮次|同一编号最多有家长首条提交和受理方一次公开回复；不允许家长继续发消息|
|记录结束|受理方回复后本条结束并只读；后续问题通过新增反馈单独提交|
|排序|列表按记录最近更新时间从新到旧；详情沟通记录按消息时间从新到旧，最新消息在上|
|学生快照|按提交时孩子、学校及相关业务资料留存，供受理及历史记录识别；家长详情不显示学校/学生快照字段|

##### 3.2 身份、孩子、权限与可见范围

1. **当前家长角色**：双身份账号切换到家长角色时，只查看家长角色提交的本人反馈；同一账号的教师角色记录不并入家长列表。
2. **本人记录隔离**：列表按当前家长角色和提交账号查询。本人提交的历史记录不按当前选择的孩子、当前孩子列表、学校或孩子关系再次过滤。
3. **同家庭其他家长隔离**：即使两位家长关联同一孩子或同属一个家庭，其他家长账号也不能查看当前家长提交的反馈。
4. **孩子切换**：打开提交表单时，以当时孩子选择器选中的孩子作为本条记录关联对象。表单基本信息卡中的学校和学生名称从该孩子关系回写，不提供手工编辑。
5. **在读资格**：只有提交时关系仍有效且孩子为在读，才允许创建新反馈。毕业、离校、关系失效、状态为空或无法核验均阻止提交。
6. **状态变化**：提交后孩子转校、毕业、离校或解绑，不改写已提交反馈的学生/学校快照，不影响家长本人查看记录；孩子资料按现有一年可见规则退出孩子列表后，家长仍可在本人反馈列表查看历史记录。
7. **学校 Web 隔离**：家长小程序提交的记录不回显到学校 Web。学校人员不能仅因学校、班级或孩子关系而查看家长提交的正文、附件或消息。
8. **受理方范围**：按当前所选孩子对应学校在提交时的负责人配置分配给代理商或运营平台。受理组织内有权限的账号可查看和答复；非指定受理方不可查看正文、图片或历史消息。
9. **负责人变更**：记录仍处于待回复时，按学校最新负责人配置转给新受理组织。转派后原受理组织立即失去正文和附件访问权；新受理组织可查看完整历史并继续处理。家长本人查看权不变。
10. **提交资格与提交时复核**：页面可打开不代表可以提交。提交动作需重新确认家长身份、当前所选孩子与家长关系、学校关联以及在读状态；校验结果以提交时为准。

##### 3.3 与学校 Web 一问一答规则对齐

1. 学校 Web PRD v1.14的原规则是：“学校提交首条反馈后等待受理方回复；收到回复后，这条记录结束对外问答。”家长小程序使用相同的一问一答业务边界。
2. 家长提交成功后生成新的反馈编号，记录状态为待回复，沟通记录出现家长“提交”消息及提交时间。
3. 指定受理方最多向该记录发送一次公开回复。回复成功后状态变为已回复，沟通记录出现“回复”消息及回复时间；同一记录结束。
4. 家长不能在原编号下追问、补充、修改、撤回或删除已提交内容；页面不展示相关按钮、弹窗或状态筛选。
5. 如需说明另一问题或继续补充新的问题，家长另建一条反馈。新记录使用新编号，不覆盖、合并或追加到旧记录。
6. 通知是否送达与反馈状态分别处理；通知失败不能把待回复变成已回复，也不能让家长误以为已获得答复。

###### 6.1.2 列表卡片及筛选

1. 筛选项固定为全部、待回复、已回复，不出现已撤回或其他状态。
2. 每条卡片展示反馈类型、状态、正文摘要及最近消息时间；整卡点击进入同一编号的反馈详情。
3. 状态显示与学校 Web 使用相同文字：待回复、已回复。不能将通知状态当作反馈处理状态。
4. 列表只加载当前家长角色和本人提交账号的记录；切换当前孩子不改变列表内容。
5. 列表按最近一条公开消息的时间从新到旧排列；尚未回复记录按提交时间排序。
6. 新提交的反馈在创建成功后进入列表并显示待回复；收到受理方回复后刷新为已回复并按新更新时间重新排序。

###### 6.1.3 空态、读取异常与返回

|情况|页面表现|处理|
|---|---|---|
|尚无本人记录|展示无记录空态及提交反馈入口|不显示其他家庭成员或其他角色的记录|
|当前筛选无结果|展示对应状态无记录提示|切换筛选或新建反馈|
|列表读取失败|明确提示暂时无法加载并提供重试|不将加载失败伪装成空列表|
|孩子已解绑或不再出现在孩子列表|本人历史记录仍显示|使用提交时的内容和学生/学校关系保存历史记录；列表不要求当前孩子仍可选|
|当前角色切换|重新按新角色加载列表|教师身份提交的记录不混入家长列表|

|附件图片|是|选填，JPG/JPEG/PNG；最多9张；每张不超过10MB|只拒绝不合格或超额图片，不清空其他有效图片|

家长在孩子切换器选择孩子后打开表单；学校名称与学生名称由该孩子关系回写，卡片不可编辑。本表单没有孩子切换控件，关联对象固定为打开表单时所选孩子；要为另一名孩子提交，应返回孩子切换处改选后重新打开表单。

###### 6.2.3 提交流程

1. 家长选择当前孩子后打开反馈表单。
2. 页面在反馈类型之前显示学校名称、学生名称只读卡片，并读取该孩子当前状态。
3. 如该孩子当前状态为在读，家长可选反馈类型、填写内容并可选上传图片；非在读、关系无效或状态无法核实时，显示不可提交原因。
4. 点击提交时再次核验当前家长身份、家长与孩子关系、孩子学校关系及孩子在读状态；不能仅依赖打开页面时的缓存值。
5. 校验通过后创建新反馈编号（同一字段作为记录ID），保存学校/学生提交时快照、首次“提交”消息及附件，初始状态为待回复。
6. 创建成功后返回本人反馈列表，列表中出现新记录；提交失败时停留在表单且不创建半条记录。
7. 后续受理方最多回复一次。家长收到回复后查看原记录；需要提出其他问题时另行新建反馈。

###### 6.2.4 孩子状态、关联和附件校验

|校验项|通过条件|不通过时的处理|
|---|---|---|
|家长身份|提交账号当前处于家长角色|拒绝创建；说明需切换到家长角色并保留表单|
|家长与孩子关系|提交时家长仍可提交该孩子相关反馈|拒绝创建；不泄露该孩子是否存在于其他家庭账号|
|孩子状态|提交时孩子为在读|毕业、离校、状态为空或状态无法确认时拒绝；说明暂不能为该孩子提交新反馈|
|学校名称|能读取当前孩子提交时有效学校名称|阻止提交并说明学校资料不可用|
|学生名称|能读取当前孩子提交时有效姓名|阻止提交并说明学生资料不可用|
|反馈类型|问题反馈或功能建议之一|未选择时提示选择类型|
|反馈内容|去除首尾空白后非空，且不超过500字|指出为空或超限；保留输入|
|图片张数|最多9张|第10张不加入；已选有效图片继续保留|
|图片格式|JPG/JPEG/PNG|拒绝不支持图片，保留其他有效图片|
|单张图片大小|每张不超过10MB|拒绝超限图片，保留其他有效图片|
|图片读取|图片读取成功且完成|读取中暂不允许提交；读取失败提示重新选择|

孩子状态“毕业”“离校”“在读”以现有业务资料为准；原型沿用现有示例状态，不新增业务状态字典。孩子不在读时不得通过切换基本资料卡文字绕过提交限制。

###### 6.2.5 取消、重复点击与提交失败

1. 未输入内容、未选择类型、未添加图片时，取消或返回直接退出，不创建记录。
2. 已编辑类型、正文或图片时离开，先确认是否放弃；继续填写回到原表单并保留输入，确认放弃后清除本次未提交内容。
3. 提交处理中再次点击不能创建多个编号；同一次提交动作最多创建一条记录。
4. 资格复核、内容校验或创建失败时，留在原表单，保留仍有效的正文、类型及图片。
5. 若提交过程中所选孩子关系、学校关系或在读状态已变化，以提交时核验结果为准；拒绝时说明原因，不创建记录。
6. 关闭表单后再次新建视为一次新提交；不得自动将新内容追加到已有编号。

###### 6.3.2 反馈信息卡

1. 反馈编号显示在详情信息区前部；该编号同时作为记录ID。
2. 反馈类型与状态同行显示，状态靠右对齐；状态只显示待回复或已回复。
3. 完整显示家长首次提交的内容与该消息附件，不只显示摘要。
4. 不单独展示提交时间字段；首次提交时间展示在沟通记录的“提交”消息右侧。
5. 详情不显示学校/学生快照、联系电话、受理组织内部资料或内部处理消息；基本信息卡只出现在新建表单。
6. 历史记录即使对应孩子已解绑、转校或已从当前孩子列表移除，也可从家长本人列表打开；页面仍显示提交的原始业务内容及公开消息。

###### 6.3.3 沟通记录、顺序与状态

1. 时间线按消息发生时间倒序排列，最新消息在上，时间靠消息行右侧对齐。
2. 每条记录均展示家长本人首条“提交”消息和提交时间。
3. 待回复记录只有“提交”消息，状态为待回复。
4. 已回复记录在“提交”消息之前显示一条受理方“回复”消息及回复时间，状态为已回复。
5. 消息内容和已提交附件只读；页面不展示追问、撤回、修改、删除入口，也不提供对应弹窗。
6. 受理方已经回复但详情缓存状态仍为待回复时，重新读取最新状态和公开消息；不得展示可继续发言入口。
7. 附件属于对应消息；图片打开失败时不删除消息或改变状态。

###### 6.3.4 无权、记录失效或读取异常

|场景|页面表现|处理|
|---|---|---|
|编号缺失或格式错误|不展示反馈内容|返回本人列表并说明记录无法打开|
|记录不属于当前家长提交账号|不透露记录是否存在及正文|拒绝展示并返回本人列表|
|当前账号切换为教师角色|家长记录不作为教师记录展示|切回家长角色后重新读取|
|孩子关系解除、转校或孩子不在当前列表|本人历史记录仍可打开|展示当时提交的业务内容；不要求该孩子仍在当前选择器内|
|受理方已经回复|显示已回复状态和回复消息|本条记录结束，不提供再次发言入口|
|记录读取失败|提示暂时无法读取并提供重试|不把失败伪装成空记录|
|图片打开失败|保留正文、状态和消息时间|单独提示图片暂不可查看|

#### 7. 业务信息与学校 Web 对齐

##### 7.1 一条家长反馈应关联的信息

|信息|家长端保存规则|页面是否展示|
|---|---|---|
|反馈编号/记录ID|同一个唯一编号；不另设记录ID|列表和详情可见|
|来源角色、提交账号|提交时取当前家长角色与账号稳定标识|用于本人隔离；不向其他家长暴露|
|提交人姓名、联系电话|提交时身份快照|详情不展示联系电话|
|关联孩子|取打开表单时当前选中的孩子稳定身份|用于关联、权限复核和提交时快照；详情不显示孩子快照字段|
|学校名称、学生姓名|提交时根据孩子与学校关系回写并保存快照|新建表单只读卡展示；详情不展示快照|
|反馈类型、正文|家长所选类型及首次提交内容|详情完整展示|
|附件|关联首次反馈消息；最多9张，每张不超过10MB|表单提交前可移除；提交后只读|
|提交/更新时间|首次提交和受理方回复各自时间|列表显示最近更新时间；详情消息旁展示各自时间|
|状态|待回复、已回复|列表筛选、卡片及详情展示|
|受理组织|按所选孩子所属学校提交时的当前负责人配置确定；未回复前按新配置转派|家长不展示内部组织分配信息|
|公开消息|家长首次提交和受理方至多一次回复|详情倒序展示|
|孩子状态快照|提交时状态；新建资格仅在读|用于受理与历史识别；详情不展示状态快照|

##### 7.2 与学校 Web 的边界

1. 学校 Web PRD v1.14的原规则为：“学校提交首条反馈后等待受理方回复；收到回复后，这条记录结束对外问答。”家长小程序采用相同问答轮次和状态文字。
2. 对家长记录，家长是首问方，代理商或运营平台为该校对应受理方；受理方只能回复一次，回复后状态为已回复。
3. 学校账号不能因孩子在该学校就查看家长小程序来源记录；学校 Web 不回显家长提交的记录。
4. 受理组织仅限提交时指定的受理方；未回复前发生负责人转派时，按当前确认规则移交完整沟通历史与附件，原受理组织立即失去正文及附件访问权。
5. 家长详情只展示公开沟通内容；受理方内部记录、学校内部记录和其他家庭成员记录均不可见。

#### 8. 异常和恢复规则

|编号|场景|预期结果|
|---|---|---|
|P-ERR-01|账号当前不在家长角色|拒绝打开受保护记录；切换为家长角色后重新加载|
|P-ERR-02|当前家长与所选孩子关系失效|拒绝创建新记录并保留未提交表单；不影响既有本人历史记录查看|
|P-ERR-03|孩子毕业或离校|拒绝新建；不得改变孩子状态或绕过提交资格；历史记录仍可查看|
|P-ERR-04|孩子状态未知或无法读取|拒绝新建并提示暂无法确认在读状态；保留内容|
|P-ERR-05|学校名称或学生名称缺失|卡片标明必要资料不可用且不可提交，不以空值建立记录|
|P-ERR-06|反馈类型未选择|提示选择类型，正文和图片保留|
|P-ERR-07|正文为空、全空格或超过500字|显示具体原因；不生成编号，保留表单|
|P-ERR-08|选择超过9张、格式不符或单图超过10MB|拒绝不合格图片；其他有效图片保留|
|P-ERR-09|重复点击提交|同一动作至多生成一条记录和一个编号|
|P-ERR-10|反馈详情无权或编号无效|不泄露内容、附件或编号归属；回到本人列表|
|P-ERR-11|受理方已回复但页面状态未刷新|详情刷新后显示已回复及唯一回复；没有追问入口|
|P-ERR-12|列表、正文或附件读取失败|显示可识别的失败信息并允许重试；不伪装为空|
|P-ERR-13|历史数据包含已撤回或多条追问|不得静默将已撤回映射为待回复/已回复，也不得删改历史消息；历史迁移/展示方式单独确认|
|P-ERR-14|孩子在提交前切换、转校、解绑或状态变化|以提交动作时校验到的当前关系和在读状态为准；无效时拒绝创建并保留表单|

#### 9. 需求验收标准

1. 家长反馈列表仅展示当前家长角色、当前提交账号的记录；同家庭其他家长账号的记录不可见。
2. 列表只提供全部、待回复、已回复筛选，不出现已撤回筛选。
3. 提交表单在反馈类型前显示学校名称和学生名称，两者只读且来自打开表单时当前所选孩子关系。
4. 当前所选孩子仅在提交时仍为在读且关系可核验时可新建；毕业、离校或未知状态均不能创建。
5. 新反馈的创建动作生成一个唯一反馈编号，该编号同时为记录ID；提交成功状态为待回复。
6. 每条记录时间线恰有一条家长首条提交，受理方可有至多一条回复；提交动作和具体日期时间可见，消息倒序展示。
7. 受理方回复后状态为已回复，本条只能查看；页面无追问、撤回、修改、删除入口及其弹窗。
8. 需要提出另一个问题时，家长能够新建独立反馈，新记录获得独立编号，不覆盖既有记录。
9. 本人历史记录不因当前切换孩子、解绑、转校或孩子离开当前孩子列表而消失；同家庭其他家长仍不可查看。
10. 家长详情不显示学校/学生快照、联系电话及受理方内部消息。
11. 正文、附件张数、格式、单张大小与权限校验满足本文件规则。
12. 学校 Web 不出现家长小程序来源记录。
13. 本候选保持未定版、未发布，活动原型基线不变，除非用户另行确认发布。
