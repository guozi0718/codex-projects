# 原型字段映射与权限规则

来源：客户反馈功能项目 `E:/codex/运营后台/客户反馈/任务/T-20261116-01-小程序反馈字段权限契约/资料/01-反馈记录字段契约草案.md`、用户Q06-Q25答复及Web客户反馈PRD v0.6。物理数据库/接口字段名须由真实后端数据字典确认；下文是可联调的业务语义，不表示已落库。

## FeedbackRecord（记录主表）

| 字段 | 本原型语义 | 规则 |
|---|---|---|
| feedbackNo | 反馈编号，唯一记录主键兼业务编号 | 不设第二个recordId/feedbackId；消息、附件、通知和审计均引用它。原型DEMO编号由离线脚本模拟，正式编号须服务端生成。 |
| sourceRole / sourceChannel | 提交来源角色 / mini-program | teacher或parent由当前端上下文确定；服务端不得信任客户端传参。 |
| submitterAccountId | 提交账号稳定ID | 列表按当前角色+该账号ID；不按当前schoolId/studentId裁切本人记录。 |
| submitterNameSnapshot / submitterPhoneSnapshot | 提交姓名、绑定电话快照 | 提交时保存；前端无手机号录入项。 |
| regionId / regionNameSnapshot | 提交时地区关系快照 | 记录字段，不作为提交方列表筛选条件。 |
| schoolId / schoolNameSnapshot | 提交时所属学校快照 | 用于记录、受理路由和审计；不用于筛除本人历史。 |
| studentId / studentNameSnapshot / studentSnapshot | 家长提交时所选学生快照 | 教师为空；家长按提交学生保存快照。孩子资料解绑/转校仍按既有逻辑保留一年；一年后家长仍看本人记录并显示此快照。 |
| feedbackType / title / firstContent | 类型、可空标题、首条正文 | 当前页面无标题输入；首条正文与首条消息正文保持一致。 |
| attachments | 附件引用集合（按messageId归属） | 不持久化DataURL；离线预览图只在内存中显示。正式文件由受控文件存储和权限接口管理。 |
| createdAt / updatedAt / status / version | 首次时间、最近有效更新时间、状态、并发版本 | 状态三态“待回复/已回复/已撤回”，新建“待回复”。时间和版本正式以服务端为准。 |
| receiverRole / receiverOrganizationId / receiverAccountId | 当前指定受理关系 | 按提交学校当前负责方配置指向代理商或运营平台；同受理组织具反馈权限账号可读。 |
| receiverHistory | 受理分配变更历史 | 待回复记录随学校负责方配置转派；同一反馈编号不变；转派后旧方立即失去正文/附件访问，新方可读完整历史和附件。 |
| withdrawal / deletion | 撤回及合法软删除事实 | 可空，保留所需审计；本原型不新增撤回/删除操作。 |
| requestId | 写入幂等关联 | 正式写请求应由服务端校验幂等；示例值为虚构数据。 |

## FeedbackMessage（消息）

`messageId`独立稳定ID；关联`feedbackNo`；保存`messageType`、作者账号/角色/姓名快照、接收账号/组织、正文、消息级附件、服务端顺序、服务端时间、版本、阅读事实、撤回/删除占位事实及`requestId`。首条消息与记录`firstContent`在正式服务端需事务一致。

## AttachmentReference（附件）

每个引用包含`attachmentId`、`feedbackNo`、`messageId`、文件名、MIME、字节数、校验和、存储键、上传时间、保留期限及上传状态；下载时重新按提交人或当前受理方鉴权并留访问审计。转派后旧受理方不能再读正文和附件，新受理方可读完整历史附件。

## NotificationRecord / AuditEvent

通知记录关联通知ID、requestId、反馈编号、回复messageId、接收账号、渠道、模板版本、服务商流水、状态、时间、操作者及失败码；通知状态与反馈三态分开。审计记录包含eventId、反馈编号/可选messageId、操作者账号及快照、端/角色、动作、服务端时间、结果、前后版本和requestId；转派需记录前后组织及学校配置依据。

## ListResponse 与访问范围

列表返回授权范围内的`items`、权威`total`、分页字段、`hasMore`和requestId。小程序服务端按当前角色+提交账号ID查询；同账号教师/家长身份分开展示；同校其他教师和同家庭其他家长账号不可见。详情按反馈编号重新鉴权。学校Web只显示学校来源记录，不回显教师/家长小程序记录；同校有反馈权限账号可查看学校自行提交的记录。受理组织内有权限账号可见，运营账号仅当运营平台为当前指定受理方时可见。

## 当前演示边界

教师/家长HTML当前仅提供静态虚构账号与本地内存记录，`ZXH_HELP_PREVIEW`可供评审观察授权列表语义。没有真实登录账号、后端查询/鉴权、持久化、上传、推送或Web回显。演示结构不得直接作为生产物理字段名；生产服务端必须重新鉴权，不能把前端筛选当隔离措施。
