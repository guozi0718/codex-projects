# 跨项目原型演示说明统一要求

版本：v1.0（交付稿）  
日期：2026-11-13  
适用对象：移动端小程序原型、家长端、教师端、学校端、运营管理端，以及其他采用完整基线维护的业务原型。  
主要读者：产品设计、交互设计、前端开发、测试及参与原型修改的 AI 协作工具。  
实施状态：作为接收项目的接入与验收要求；是否已落实，以该项目的实际实现和验收证据为准。

## 1. 目的与使用边界

本规范统一原型中“演示说明”的内容组织、展示效果、场景操作和维护方式，使不同项目、不同端、不同会话开发的页面能够保持一致的阅读与演示体验。

演示说明是原型内部面向技术开发的辅助层，承载当前页面的规则、交互、权限、状态与演示操作。它不属于正式产品面向最终用户的业务功能。

本文件是一份可跨项目转发的统一要求，不要求为每个业务页面再写一份 Markdown、Word 或 PRD 来复述其演示说明。页面级说明应直接维护在对应原型及其配置中。接入项目已有的业务需求文档、接口文档和合规流程仍按原制度执行。

接收项目实施本规范时，应保持已确认的业务字段、顺序、文案、权限及交互逻辑；对这些内容的变更仍须有该项目的明确授权。分发本文件本身不代表所有项目已获准进行批量改造。

### 1.1 要求等级

| 等级 | 含义 | 验收处理 |
|---|---|---|
| 必须 / 不得 | 接入后应满足的硬性要求 | 不满足时不得声明相应能力已通过 |
| 应 | 默认执行要求 | 因项目形态不适用时说明原因及替代方式 |
| 可 | 条件适用或可选增强 | 未实现不影响其他已适用要求的验收 |

后台浮窗的拖动、收起和独立打开，对采用浏览器桌面后台原型的项目属于应实现能力；受运行环境限制时，按第 7 节提供降级并记录验证结果。纯移动原生运行环境无需模拟浏览器独立窗口。

### 1.2 来源与要求性质

本规范以智小徽教师端、家长端当前 HTML 原型的共享演示说明组件及页面配置为参照，参考文件包括 `demo-panel.js`、`demo-panel.css`、`teacher.js`、`parent.js`、`help-v1.js`。

已核验的参照行为包括：移动原型宽屏右侧栏、窄屏内浮层、切页跟随、小节折叠、搜索高亮、本页操作置前、通用入口置后、超过八项的操作折叠，以及家长端校徽三个 Tab 各自的说明。共享组件源码还包含后台浮窗、拖动、收起及独立打开机制。

下文的覆盖登记、上下文契约、嵌入模块协作、生产隔离和验收门槛，是为跨项目复用明确的工程要求；不据此宣称现有各端已经全部实现或通过验收。本文不引用国家标准或平台官方限制数值，不把项目约定称为官方规范。

## 2. 核心原则

| 编号 | 原则 | 要求 |
|---|---|---|
| G-01 | 页面与说明同步 | 当前页面、当前 Tab 或关键场景改变后，说明必须对应当前界面，不能继续展示上一处内容 |
| G-02 | 操作与说明就近 | 本页面的演示场景及状态开关集中放在本页演示说明中 |
| G-03 | 业务界面保持完整 | 不为演示添加多余的业务按钮、菜单、流程页或选择页 |
| G-04 | 统一组件 | 同一端共享展示组件，多端复用相同机制；业务模块提供内容和动作，不各自重做面板 |
| G-05 | 说明服务开发 | 写清规则、条件、落点和边界，避免宣传性描述和空泛的功能介绍 |
| G-06 | 原型与真实能力分明 | 模拟登录、支付、消息、权限、客服等必须明确演示边界，不冒充真实服务 |
| G-07 | 修改同步 | 新功能和业务修改应同步维护对应说明；不能出现界面已改、说明仍旧的交付 |
| G-08 | 不增加业务栈 | 打开、搜索、折叠说明及纯场景切换不得新建业务页面；页面内 Tab 不重复入栈 |

## 3. 覆盖对象与说明定位

### 3.1 覆盖范围

接收项目必须清点当前版本的有效业务页面，至少涵盖首页、列表、详情、新增或编辑、审核、结果、登录及身份承接、帮助反馈、权限或异常页面。

说明应按“阅读上下文”定位，不能只按文件名或可见标题定位。推荐由以下信息生成稳定标识：

```text
项目 / 端 / 页面 / 页内Tab / 有独立规则的模式或场景
```

并非每条业务记录都要生成一份说明。记录不同但规则一致时，共用页面说明；规则、权限或操作明显不同的状态，应有对应小节或独立场景说明。

### 3.2 页面与 Tab 的对应规则

| 类型 | 处理要求 |
|---|---|
| 普通单页 | 按页面标识获取说明 |
| 同页多个业务 Tab | 各 Tab 的规则或操作不同时，按“页面 + Tab”分别取说明；切 Tab 原位更新面板 |
| 状态筛选 | 同规则共用说明；待审核、只读等权限或动作不同的状态须覆盖差异 |
| 弹窗、抽屉、半屏 | 简单弹层在所属页说明中描述；具有独立流程的弹层可使用弹层上下文，关闭后恢复所属页说明 |
| 新增 / 编辑 / 只读共用页 | 按模式显示相关规则，不能用新增说明覆盖编辑或只读行为 |
| 无权限或对象失效 | 告知实际兜底和返回方式，不能仍提供不适用的正常态动作 |
| 历史或后续阶段页面 | 标明当前不可从正常业务进入；如保留预览，置于演示说明并说明恢复方式 |
| 嵌入模块 | 外层容器与内嵌业务的说明归属必须明确，见第 11 节 |

例如，智能校徽同一页面的“我的校徽 / 校徽办理 / 办理记录”三个 Tab，应分别展示持有规则、办理规则、记录规则和对应演示操作。它们不因说明不同而变成三层业务页面。

### 3.3 覆盖登记与缺失处理

覆盖关系优先保存在配置、代码或自动检查结果中，无须另建逐页说明文档。

新增及本次修改的有效页面必须有可用说明。规则简单的页面可以简短，但不能只显示路由 ID、空面板或“待补充”。

迁移既有基线时，历史缺口应逐项登记为待补齐，不能把页面总数直接当成有效覆盖数。可共用说明的 Tab 应登记共用关系；退出业务链路的存档页应单独统计，不能混入有效页面覆盖率。

## 4. 演示说明的内容要求

### 4.1 每页应回答的问题

按实际适用情况覆盖下表。简单页可合并小节；不适用的内容可以省略，不能为了齐全而编造规则。

| 内容 | 应写清的事实 | 不合格示例 |
|---|---|---|
| 页面用途与入口 | 从哪里进入、处理哪个对象、适用角色 | “本页展示业务信息” |
| 结构与字段 | 区域顺序、必填项、默认值、只读或隐藏条件 | 只有字段名称，没有行为条件 |
| Tab 与筛选 | 默认项、保留或清空条件、组合关系、统计是否随筛选变化 | 只写“支持筛选” |
| 权限与范围 | 查看和操作条件、数据范围、无权限出路 | 用“管理员可操作”省略具体条件 |
| 主流程 | 点击后出现什么、提交条件、成功与失败落点 | 把实际确认弹窗描述成直接提交 |
| 状态与异常 | 空数据、无匹配、已处理、失效、重复操作等适用状态 | 用一句“异常时提示”覆盖所有情况 |
| 返回与恢复 | 来源页、返回落点、刷新或直达缺上下文时如何处理 | 详情无对象仍声称可正常展示 |
| 数据与联动 | 数据源、统计口径、跨端联动及模拟范围 | 把演示定格值说成实时统计 |
| 演示操作 | 每个场景改变什么、持续多久、如何恢复 | 开关生效后无法判断当前状态 |

### 4.2 文案组织

1. 开头用一小段概述说明页面用途、入口和当前范围。
2. 较长内容按 `【入口与返回】`、`【字段与校验】`、`【权限与范围】`、`【状态与异常】`、`【演示边界】` 等小标题组织。
3. 长段落应分段，同一小节围绕同一主题；避免整屏连续文字。
4. 标题、按钮、字段和状态名称必须与当前原型实际文案一致。
5. 条件明确写成“当……时……；否则……”，必要时说明提交前二次校验。
6. 已确认规则、演示假设、历史存档和待确认事项必须区分；建议不得写成已确认业务规则。
7. 不要求加入源码函数名、历史日期或实现细节；只有帮助开发理解必要约束时才保留。
8. 不复制其他端不适用的权限、数据或操作。共用规则可共享，角色差异须显式说明。

### 4.3 内容示例

以下仅示范写法，不向其他项目新增请假业务规则：

```text
本页从请假列表点击记录进入，展示所选单据当前状态及可用操作。
【入口与返回】返回原列表并保留筛选条件；无有效单据上下文时按项目已确认规则回到列表。
【状态与权限】操作区由当前单据状态和本人权限共同决定；提交时再次核对，已被处理时不得重复提交。
【演示边界】状态切换使用本地演示记录，不调用真实审批接口；刷新后的恢复方式以本页配置为准。
```

## 5. 面板结构与基础交互

### 5.1 统一结构

面板从上到下保持以下顺序：

1. 当前上下文标题、关闭入口，以及适用的面板工具。
2. 本页说明搜索框与匹配计数；无正文时可省略搜索框。
3. “演示操作”：本页场景按钮、状态开关和预览入口；没有操作时整组省略。
4. “说明”：概述、可折叠小节以及适用的“全部展开 / 全部收起”。
5. 通用入口：项目确实提供的登录起点、更新日志、总览、外观切换等。

面板标题必须使用业务名称，不能只用路由 ID 或源文件名。通用入口不得抢占本页场景区；不存在的入口应省略，不能保留死链接。

### 5.2 开闭与自动跟随

- 初始进入页面不应自动弹出说明遮挡业务，除非该项目有明确约定的评审启动场景。
- 点击统一的“演示说明”入口打开；再次点击入口或关闭按钮可收起。
- 桌面右侧栏打开后，切换业务页或执行场景动作应保持面板打开，并更新为当前说明。
- 窄屏内浮层允许在跳转或执行场景动作后收起；再次打开必须对应最新上下文。
- 未打开时，页面变化不得强行弹出面板。
- 上下文改变时，旧说明的搜索词、匹配位置及折叠状态应重置，滚动回到新说明起点。
- 同一上下文内重绘时，应保留可继续使用的搜索、展开和阅读位置，不因一次开关操作反复跳回顶部。

### 5.3 小节折叠

与参照组件保持以下默认规则：

| 情形 | 默认效果 |
|---|---|
| 有开头概述，后接多个小节 | 概述可见，小节默认收起 |
| 正文直接以小标题开头，无概述 | 第一小节默认展开，其余收起 |
| 点击某小节标题 | 只切换该小节展开状态，不改变业务页 |
| 点击全部展开 | 展开当前说明所有小节 |
| 点击全部收起 | 收起所有可折叠小节，概述仍可见 |

此规则仅适用于“演示说明”的小节。业务页常见问题等控件的默认展开状态，仍遵守该业务本身已确认的要求，不套用说明面板规则。

### 5.4 搜索

搜索范围为当前上下文的说明正文，不是全项目业务搜索，也不用于搜索业务列表。

必须支持输入后高亮匹配文字、显示匹配数量、展开命中小节并定位首处。当前命中与其他命中应有可区分的高亮；无匹配时明确提示“无匹配”，不隐藏原文。

桌面键盘 Enter 跳转下一处，Shift + Enter 跳转上一处，到末尾可循环。清空搜索后移除高亮，恢复搜索前的手动折叠意图。搜索定位只能滚动说明区域或独立说明窗口，不能拉动手机框或业务页面。

### 5.5 本页操作与“更多”

按钮使用紧凑胶囊布局并自动换行；开关行占整行。操作超过八项时，默认展示前八项，其余放入“更多 N 项”；展开后能够再次收起，不能丢失动作或改变选中状态。

优先放当前阶段常用场景，标有“已隐藏”“站内”“后续阶段”的历史或低频预览入口置后，同组内保留原顺序。不得仅凭关键词误判而删除入口；无法可靠解析旧写法时，应保留原内容并逐项适配。

## 6. 移动原型的宽屏与窄屏效果

### 6.1 宽屏右侧栏

手机框右侧剩余空间足够时，在手机框外显示右侧栏；手机框位置、尺寸和缩放保持不变。不能通过挤窄手机内容或平移业务界面腾出说明空间。

右侧栏必须可以独立滚动，标题和搜索区域吸顶；长内容不得超出可视高度。面板不受手机框圆角或 `overflow` 裁切。

### 6.2 窄屏内浮层

空间不足时，面板回到手机框内显示，保留相同内容、搜索、折叠和操作能力。点击浮层外部关闭，点击面板内部不应误关。内容必须可滚动，避免横向溢出或关闭入口被遮挡。

### 6.3 默认视觉参数

以下为参照组件的项目默认值，用于复现效果，不是设备或平台强制标准。采用同一套 HTML 原型框架时应直接复用；容器尺寸不同的项目可调整，但必须保持相同可读性和交互效果。

| 项目 | 默认值或计算方式 |
|---|---|
| 右侧栏与手机框间距 | 28px |
| 右侧栏启用条件 | `可用宽度 = 窗口宽度 − 手机框右边界 − 28px − 16px`，可用宽度不小于 340px |
| 右侧栏宽度 | 不小于 340px，最多 500px，受实际可用宽度限制 |
| 右侧栏高度 | 不超过手机框高度及窗口可用高度；上下留出可操作空间 |
| 标题 / 正文 | 侧栏约 15px / 13px；正文行高约 1.8 |
| 手机内浮层 | 两侧保留约 12px，宽度随实际容器适配，不机械照抄固定宽度 |
| 手机内正文 | 约 11.5px，行高约 1.7；不以缩小到难读的方式容纳长文 |
| 风格 | 白底、浅色边框、圆角、轻阴影；搜索与当前命中有明确高亮 |

窗口缩放、浏览器缩放及手机壳显隐后应重新计算位置。侧栏模式转换不能重置业务数据、重复创建面板或累积事件监听。

## 7. 桌面后台原型的浮动说明

### 7.1 浮动与层级

学校端、运营端等宽屏后台采用浮动面板时，面板不占业务布局宽度，应允许拖动标题区域调整位置、收起为小标签、重新展开及关闭。

参照组件采用浅黄色说明面板，与业务内容形成区分；默认展开宽度约 400px、收起约 260px，左右至少保留约 12px 可操作空间。缩放后应将面板限制在可视区域，防止拖出屏幕后无法恢复。

业务弹窗、抽屉、遮罩和确认操作优先于说明面板。不同项目应按自己的层级系统适配，不能机械复制某个 `z-index` 数字而压住业务弹层。

拖动标题不能触发关闭、独立打开或正文操作；点击面板按钮也不能启动拖动。

### 7.2 收起与独立打开

收起再展开应保留当前上下文的搜索词、小节展开状态和阅读位置，不重置正在演示的业务。

独立打开时只镜像说明，不复制一套业务页面或业务数据。独立窗口的场景操作仍交给原业务页执行，原页变化后镜像同步刷新；同一原页重复点击应聚焦既有独立窗口。

关闭独立窗口或点击“返回页面”后，原页说明恢复可用。原页退出时应断开镜像关系，避免遗留失去来源的窗口或向已销毁页面发送操作。

浏览器阻止弹窗或环境不支持独立窗口时，应在当前面板给出简短提示，保留当前阅读状态；不得白屏、误开业务页或丢失演示状态。

### 7.3 键盘与可操作性

关闭、展开、搜索和操作入口应可通过键盘访问，并具有清晰的文字或可访问名称。对非模态侧栏不得错误设置阻断业务操作的焦点锁；内浮层按项目弹层规范处理焦点。

按 Esc 时优先关闭当前最上层业务弹窗；没有更高层交互时才处理演示说明。不得通过独立的全局监听同时关闭业务弹窗和说明面板。

## 8. 演示场景、状态与数据

### 8.1 动作应真实改变原型

演示按钮必须能看到对应页面、状态、数据或权限表现的变化。只有提示文字而没有场景变化时，应明确标为“能力示意”，不能冒充已实现预览。

场景名称应表达结果，例如“预览 · 无数据”“预览 · 只读权限”“场景一 · 单客服”“恢复 · 默认角色”。不同场景涉及对象、角色或筛选时，切换后这些条件必须相互一致。

### 8.2 状态生命周期

每个场景应明确以下属性，可存于配置或页内说明，不要求单独写文档：

| 属性 | 要求 |
|---|---|
| 影响范围 | 本页、本模块、本端或跨端共用；不能暗改无关模块 |
| 持续时间 | 单次动作、当前页面、当前会话或持久化偏好 |
| 恢复方式 | 再次切换、恢复默认、刷新或项目已确认的重置入口 |
| 刷新行为 | 恢复默认或续接当前场景，两者必须与实现一致 |
| 联动对象 | 明确哪些列表、详情、角标、统计或另一端会随之变化 |

互斥场景不得同时生效；一次性竞态模拟使用后应按约定复位。持久化演示偏好应使用项目及版本隔离的存储键，避免另一原型或旧版本污染当前状态。

只有演示环境允许的范围可以模拟权限变化。真实权限校验不因演示开关、URL 参数或本地存储值而被绕过。原型中的模拟角色必须与真实账号权限分开处理。

### 8.3 与真实服务隔离

切换支付、拨号、通知、审批、删除、重置等演示场景，不应意外调用生产服务、触达真实人员或修改真实业务数据。有真实服务集成的项目，应由其明确配置的测试环境承接，并遵守该项目授权。

说明应标明演示数据、模拟能力和刷新边界，避免展示真实手机号、账号凭证、学生隐私或其他不必要的敏感信息。

### 8.4 后续阶段与历史方案

后续阶段、隐藏入口、备选方案和旧版页面仅供开发理解时，应集中放在对应页说明里并清楚标识，不重新塞回正常业务入口。

这类预览不代表已纳入当前交付范围，也不自动形成新需求。预览后应有明确返回或恢复默认方式，不能使后续演示一直停留在旧版业务中。

## 9. 页面内 Tab、导航与页面栈

### 9.1 先区分导航类型

| 类型 | 正确处理 | 不得出现 |
|---|---|---|
| 页面内 Tab | 在当前页面切换内容、筛选或模式，并更新说明上下文 | 每点一次 Tab 新建同类页面 |
| 应用主导航 | 使用项目对应的主导航机制，保持约定的页面复用和状态 | 通过普通连续入栈模拟主导航 |
| 独立详情、编辑或结果页 | 根据流程进入、替换或返回，使用该项目已确认导航规则 | 循环新增列表和详情、提交后返回失效表单 |
| 说明开闭、搜索、折叠 | 只更新辅助层状态 | 为说明打开业务路由或增加原生页面栈 |
| 场景模拟 | 尽量在已有页面及演示状态中完成 | 反复开新页面冒充空态或权限切换 |

某些 HTML 原型用多个容器模拟同一个真实业务页的两个 Tab。实际小程序实现时，应按真实交互语义设计同页切换，不能照搬容器数量建立原生页面栈。

### 9.2 返回与历史记录

- 进入详情应记录必要来源及上下文；返回恢复该来源，而非再新建一个相同列表页。
- 从外部链接、消息、扫码等入口直接进入时，应校验对象和身份；缺失或失效时使用已确认的兜底。
- 页面内 Tab 是否写入浏览器历史，按接收项目已确认的交互约定执行；不能把浏览器 URL 变化等同于原生页面入栈。
- 若 Tab 使用 URL 参数续接，重复点击当前 Tab 不得新增相同历史条目；恢复历史时不得再次写入，造成回退循环。
- 支付结果、登录完成、身份切换等节点应明确保留、替换或重置哪些页面；不能无条件追加页面。
- 本规范不规定具体平台最大栈深。实施真实小程序时须按采用平台的当前能力核对，不使用记忆中的数值代替验证。

### 9.3 栈稳定性验收

接收项目必须验证连续操作后的页面栈稳定性。建议测试轮次如下，它们是本规范的测试负载，不是平台标准：

1. 同页两个或多个 Tab 连续切换 50 次，业务页面栈相对开始时增量为 0。
2. 说明开闭、搜索、折叠和“更多”操作连续 50 次，业务页面栈增量为 0。
3. 列表 → 详情 → 返回循环 20 轮，栈深恢复到原层级，无重复列表累积。
4. 执行角色或身份切换、流程完成后，栈深符合该流程约定；返回不进入无权限或已消费页面。
5. 有浏览器历史同步的项目额外检查前进、后退和刷新，不出现自写历史循环。

HTML 原型只能验证其自身 DOM、路由及历史行为。不得仅凭 HTML 切页成功，宣称未来真实小程序的导航栈已验证安全。

## 10. 共享组件与接入契约

### 10.1 职责划分

| 层 | 负责内容 | 不应承担 |
|---|---|---|
| 展示组件 | 布局、侧栏或浮层、折叠、搜索、高亮、更多、面板状态 | 具体审批、支付、权限和业务数据规则 |
| 页面说明配置 | 标识、标题、正文、小节、动作名称、适用条件和演示边界 | 自行复制一套通用面板 DOM 与样式 |
| 上下文适配 | 读取页面、Tab、模式和必要场景，通知说明更新 | 为说明额外发起业务导航 |
| 场景控制 | 切换允许的演示数据、调用受控动作、恢复默认 | 绕过真实权限或隐式修改生产数据 |

页面、Tab、模式或关键场景切换完成后，应从实际生效的业务状态更新说明，不能提前写死目标页标题。相同上下文应复用实例，事件监听、观察器及独立窗口连接在销毁时清理。

### 10.2 配置示例

以下为跨项目接入的数据契约示例，不是现有 `demo-panel.js` 的原生 API；使用现有组件时应通过适配层转换，不可直接假定示例能运行。

```json
{
  "contextKey": "parent/badge/apply/form/default",
  "title": "智能校徽 · 校徽办理",
  "intro": "办理入口与适用对象的简短概述。",
  "sections": [
    { "id": "validation", "title": "字段与校验", "text": "填写已确认的校验规则。" },
    { "id": "demo-boundary", "title": "演示边界", "text": "本场景使用本地演示数据。" }
  ],
  "actions": [
    { "id": "preview-empty", "label": "预览 · 无数据", "handlerId": "badge.previewEmpty", "stage": "current" },
    { "id": "restore-default", "label": "恢复 · 默认场景", "handlerId": "badge.restoreDefault", "stage": "current" }
  ],
  "stateScope": "session",
  "refreshBehavior": "reset",
  "restoreHandlerId": "badge.restoreDefault"
}
```

`contextKey` 是稳定的阅读上下文标识；`handlerId` 必须映射到允许的本地函数。跨项目新接入时应使用受控映射或事件，不执行来自 URL、跨窗口消息、表单或远程文本的任意代码。

可复用原有受信任配置，但应识别其与新契约的差异。说明正文若允许少量富文本，应限制标签与属性并正确转义动态值；不能在高亮搜索时破坏链接或插入可执行代码。

### 10.3 缺失与失败

开发预览环境中，未找到说明配置时应给开发者可识别的缺失提示和上下文标识，避免静默显示上一页说明；正式验收时该缺失必须消除或登记为确实不适用。

某个演示动作执行失败时，应给出简短提示，保留说明入口和可恢复的业务状态；不得因辅助层异常使业务页面整体失效。

### 10.4 构建与发布边界

演示说明的代码、调试入口、角色模拟和场景开关应归属于明确的原型或开发预览环境。正式产品发布时，应通过构建或受控配置移除相应调试能力；不能只把按钮隐藏，仍让任意参数调用模拟接口。

在已上线产品中是否另有内部诊断能力，按该项目的独立权限设计处理，不由本规范自动引入。

## 11. iframe、嵌入模块与跨端协作

### 11.1 说明归属

嵌入模块必须选定一个清晰模式：由外层统一展示内层上下文的说明，或由内层展示说明、外层提供一致的打开入口及必要桥接。不能让两个面板争抢同一个页面说明，也不能双方都认为对方负责。

外层页面只显示容器名、内层却已进入详情或编辑时，演示说明仍需对应当前有效业务上下文。只写一条“此处为某模块”不能替代内层业务说明。

### 11.2 通信边界

采用跨窗口消息时，应明确消息类型、来源窗口、项目或模块、页面、Tab、模式及允许的场景标识。接收方验证来源和载荷；不能仅凭通道名称就执行字符串脚本或任意路由。

说明同步不得反向触发重复业务跳转。外层通知内层恢复状态、内层回报已恢复状态时，应能识别相同状态，避免循环写 URL、循环重载 iframe 或重复入栈。

HTTP(S) 环境按实际允许的来源校验；本地文件环境若不能满足通信或来源校验，应提供明确的本地服务启动方式，不通过放宽为任意来源规避问题。

### 11.3 一致性

外层和内层在刷新、返回、前进及对象失效时，应保持业务页面、说明标题、动作和参数一致。退出模块后应恢复外层所属页说明，清除不再适用的内层状态和监听。

不同端共用组件时，组件版本及基础行为保持一致；端内内容按角色配置，不能为了统一效果而复制另一端不适用的数据权限或演示记录。

## 12. 新开发、修改与基线迁移流程

### 12.1 每次任务的执行顺序

1. 读取接收项目的协作规则、当前整体基线、来源版本、定版信息及本次授权范围。
2. 核对当前共享说明组件、相关页面配置及现有效果，识别页面、Tab、弹层和场景对应关系。
3. 在本次任务版本中完成业务修改及说明同步，未点名的业务保持继承。
4. 新页面接入共享组件；已有页面优先复用，不以新组件覆盖其他模块的定制内容。
5. 按第 13 节验证适用项，记录不适用、未通过和未验证项目，不能笼统写“全部通过”。
6. 保留来源、差异和验证证据，依项目制度完成快照、管理记录与最后日志。

### 12.2 既有基线首次接入

首次接入应先建立页面和 Tab 覆盖关系，识别已有说明、旧版演示入口、无效通用链接及嵌入模块责任边界；再选择一组正常页、复杂 Tab 页、长说明页、弹窗页进行接入验证，之后扩展至本次授权的其余页面。

统一组件时不得清空历史说明后只留下模板，也不得借机调整未授权的业务布局、字段和权限。旧说明包含未核实或过期内容时标明待核实，不凭经验补成确定规则。

### 12.3 多会话与多任务整合

各会话应基于已登记版本在自己的任务或新版本目录工作，保留来源版本和必要哈希。修改共享组件时必须列出所有受影响端及回归范围。

整合前比较共同来源、当前整体基线及各任务差异；不能用旧版整端文件覆盖其他会话已完成的新功能或说明。冲突必须在同一最终版本内明确合并，不能只复制某个 HTML 而遗漏它依赖的脚本、样式和说明配置。

### 12.4 交付方式

交付链接优先直达本次对应业务页，有明确评审场景时直达该场景；不同状态和相关预览放在该页面的演示说明中。总览或版本合集可保留为辅助入口，不作为默认评审落点。

不得为方便演示另造不受校验的直达参数。依赖对象、角色和权限的页面，使用接收项目已登记的有效路由及上下文恢复方式。

## 13. 验收要求与测试矩阵

验收应同时检查内容、效果、动作和业务回归。组件测试通过不能替代页面配置检查；静态截图不能替代交互验证；HTML 验证不能替代真实小程序导航验证。

### 13.1 必测矩阵

| 编号 | 检查项 | 操作与通过条件 |
|---|---|---|
| A-01 | 有效页面覆盖 | 本次新建或修改的有效页面均能打开对应说明，无路由 ID 空壳、旧页标题或遗漏 |
| A-02 | Tab 对应 | 逐一切换同页 Tab，标题、规则、动作跟随；业务内容与说明无错配 |
| A-03 | 内容一致 | 对照当前界面检查字段、默认值、权限、返回及异常说明，无过时规则 |
| A-04 | 入口与关闭 | 打开、再次点击、关闭正常；内部点击不误关；业务入口不受干扰 |
| A-05 | 宽屏侧栏 | 手机右侧空间足够时在框外显示，业务框坐标和尺寸不变，切页后保持打开并跟随 |
| A-06 | 窄屏浮层 | 空间不足时进入框内，外部点击关闭，内容可滚动，无横向溢出 |
| A-07 | 搜索 | 多处匹配、零匹配、Enter、Shift + Enter、清空均符合第 5.4 节，业务页不被卷走 |
| A-08 | 折叠 | 有概述和无概述两种默认态正确；单节、全部展开和全部收起正常 |
| A-09 | 更多操作 | 不超过八项和超过八项均可用；更多数量正确，展开后所有动作可达且不丢状态 |
| A-10 | 场景动作 | 每个本次新增或修改的按钮、开关能进入目标场景；选中状态、对象、权限和说明一致 |
| A-11 | 恢复与刷新 | 场景按声明范围持续和恢复；刷新不产生重复提交或不明状态；存储不串项目 |
| A-12 | 返回与直达 | 合法直达、缺上下文、无权限、浏览器返回前进均有正确落点和对应说明 |
| A-13 | 业务栈 | 第 9.3 节连续操作达到约定负载，无同页 Tab 或说明动作导致的页面累积 |
| A-14 | 后台浮窗 | 适用时拖动、缩放、收起展开保留阅读状态，业务弹窗优先，Esc 不越层关闭 |
| A-15 | 独立窗口 | 适用时说明镜像、场景委派、重复聚焦、关闭恢复和弹窗受阻降级均正常 |
| A-16 | 嵌入模块 | 适用时内外说明归属清楚，页面及状态同步无循环；刷新返回不丢上下文 |
| A-17 | 事件与布局 | 多轮切页开关后无重复动作、重复面板、持续累积的监听或布局跳动 |
| A-18 | 安全边界 | 场景不触达未授权真实服务；动态文本和消息不能注入可执行操作 |
| A-19 | 业务回归 | 原业务字段、顺序、权限、弹窗和返回路径保持本次授权范围内的正确行为 |
| A-20 | 交付直达 | 主链接进入对应业务页或评审场景，所需资源齐全，通用入口无死链接 |

### 13.2 建议覆盖的环境

- 移动原型：接收项目实际手机框宽度及至少一组较窄视口；测试中不得只改变窗口而不检查实际侧栏启用条件。
- 桌面原型：一组能容纳右侧栏的宽窗口、一组不足以容纳侧栏的窗口，以及较低窗口高度。
- 缩放：常规比例及较大浏览器缩放，确认说明和业务关闭按钮可达。
- 后台：具有真实弹窗或抽屉的一页，验证遮罩、焦点及 Esc 层级。
- 同页 Tab：至少一个拥有两项以上 Tab 且说明不同的页面。
- 长内容：多小节、多匹配搜索、超过八项演示操作。
- 有嵌入模块或独立窗口时，分别验证正常路径及不支持或失联时的降级。

### 13.3 通过门槛与证据

本次新建、修改及受共享组件改动影响的页面，其适用必测项应全部通过。真实小程序尚未实现时，将原生栈验证明确标为“未验证”，不得写成已完成。

验收记录至少标明项目、端、基线版本、说明组件版本、页面或 Tab、测试环境、测试结果及未解决项。截图、录屏或自动化结果随现有任务资料保留即可，不要求为每页另出说明文档。

下列情况阻止声明该范围已完整接入：说明与当前 Tab 错配；缺少有效页说明却计入覆盖；演示操作未生效却标为已实现；说明挡住关键业务操作；反复操作导致页面或历史无界累积；嵌入状态循环；调试动作误触真实服务。

## 14. 最低交付清单

接收项目完成接入或相关功能开发后，应具备：

- [ ] 可运行的完整端版本，以及本次修改页或场景的直达入口。
- [ ] 统一演示说明组件，或与既有框架相适配的等效实现。
- [ ] 当前页面、Tab 和必要状态的说明配置及场景动作。
- [ ] 明确的模拟数据范围、刷新行为和恢复方式。
- [ ] 有效页面及 Tab 的覆盖关系，可由配置或检查程序读取。
