# 反馈详情、撤回与追问规则｜Q26-Q30

## 列表与详情

列表卡片是进入详情的唯一显式入口之一，显示“查看详情”提示。打开详情时以当前角色和当前提交账号重新校验本人记录；原型使用演示账号/数据，不代表生产授权。

详情只呈现用户可读业务信息：反馈编号、状态、类型、提交时间、完整首条内容和附件、后续处理/追问消息与附件、可见的撤回结果/原因。遵照Q26，教师详情不呈现学校快照，家长详情不呈现学校或学生快照；手机号、权限ID、受理组织ID、版本/requestId等内部字段不呈现。孩子快照仍在记录模型保留，供历史关系/后端业务，不作为详情展示。

## 撤回

| 项目 | 规则 |
|---|---|
| 资格 | 状态为待回复且不存在任何处理方回复；已回复、已撤回不可操作 |
| 确认 | 点击“撤回反馈”先打开确认弹窗；原因选填 |
| 成功 | 不物理删除记录、消息或历史附件；记录状态改为已撤回，追加撤回时间/账号/原因语义和审计事件；列表保留此记录 |
| 后续 | 已撤回详情仍可查看，不提供追问或补充入口 |
| 失败/竞态 | 原型提交前复查状态；生产服务端还须按反馈编号、本人+角色、最新状态/版本原子复验；状态已变则拒绝且保留详情上下文 |

## 追加说明与追问

- 待回复时可追加说明或催问，消息写在原 `feedbackNo` 下，当前状态保持待回复。
- 已回复时可追问；写入原 `feedbackNo` 的消息时间线后，状态回到待回复，等待受理方新回复。
- 已撤回后禁止追加。
- 每条追问正文沿用现有500字上限；每条最多9张图片，每张≤10MB。读取期间禁止提交，失败可重试，暂选附件可移除。
- 新消息具有独立消息ID、作者角色/账号快照、创建时间、附件引用、requestId、版本与审计事件语义；不生成新反馈编号、不覆盖首条正文或附件。
- 本地演示以脚本内存更新记录/消息/状态并即时刷新详情和列表。刷新后重置；并未写入数据库或发送通知。

## 生产边界

前端动作入口仅为演示；生产必须由服务端按当前登录角色+本人账号、反馈状态、处理方消息事实、记录版本与附件范围重新校验，幂等追加消息/撤回事务并生成服务端时间与审计。通知、状态并发、服务端字段映射及真实持久化均未实现。

## 演示路径

- 列表点第一条“待回复”样例：查看全部信息；可补充/催问，也可撤回并选填原因。
- 列表点第二条“已回复”样例：查看受理方回复；追问追加至原反馈编号，状态改为待回复。
- 列表点第三条“已撤回”样例：查看保留的历史内容；不可继续操作。
- 教师和家长端都提供相同三态操作演示；家长详情按Q26隐藏学生/学校快照。
